QS6.1: The heuristic function that was used was a summation of the manhattan distance from the pacman to the closest corner location, 
        and the total minimum distances between all remaning dots. Essentially, if the maze had no walls, this would give the minimum distance it would take to eat all
        the remaining food in the maze. The strength is that it can give quite an accurate huristic if there were minaml walls in this path. However, the disadvantage is that
        it would be quite inaccurate if there was a wall blocking the minimum path calculated by this heuristic function and required the pacman to take a huge detour. 

QS7.1: The heuristic function that was implemented calculated the minimum maze distances to all points on the maze and took the maximum of these values (ie. minimum distance to the farthest food location) 
        This is consistent as the distance to the farthest food location cannot increase/decrease at a greater rate than the number of steps taken.  
        The strength of this method is that it does not overly underestimate the actual cost to eat all foods, allowing the search algorithm to not expand out to too many nodes. 
        The potential weakness is that if there is a lot of food and a large maze size, then computing the BFS for all these food points, would be computationally heavy.
